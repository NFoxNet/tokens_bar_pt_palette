# TokensLimitsExtension v0.0.5.3 — предварительный выпуск

Версия включает завершённую работу по устойчивости провайдеров и управлению их UI-поверхностями. Релизный gate дополнен криптографической проверкой MSIX, которая работает с self-signed сертификатом без установки его в Trusted Root.

v0.0.5.1 и v0.0.5.2 не публиковались: в .5.1 сертификат передавался в MSBuild неверно, а .5.2 собирала подписанные пакеты, но проверка Authenticode остановилась из-за недоверенной корневой цепочки на GitHub runner. Эти версии остаются в истории; публикуемый кандидат — v0.0.5.3.

## Что изменилось

- UI страниц провайдера и Dock повторно используется при переключении настроек; отключённые поверхности снимают подписки и не обновляют данные.
- Общий cache сохраняет последнее значение при временной ошибке обновления, а действия восстановления показывают следующий шаг и копируют безопасную диагностику.
- Чтение Codex session/auth файлов, HTTP-ответы провайдеров и внешние CLI ограничены по объёму, времени и памяти; JSONL читается инкрементально с сохранением неполной последней строки.
- Release workflow собирает x64 и ARM64, сверяет CMS-подпись и точный signer-сертификат с выпущенным `.cer`, проверяет digest подписи для `[Content_Types].xml` и `AppxBlockMap.xml`, сверяет SHA-256 каждого payload block, проверяет package identity/COM CLSID/обязательные файлы и allowlist артефактов.
- На одноразовом x64 GitHub runner workflow временно добавляет `.cer` в `LocalMachine\TrustedPeople`, устанавливает и удаляет пакет с сохранением данных, затем требует от Windows конкретную ошибку подписи/целостности после синхронного изменения ZIP timestamp и изменения DOS archive flag только в central directory. Manifest, block map и байты payload остаются читаемыми. Сертификат и тестовый каталог удаляются после проверки.
- SHA-256 sums проверяются повторно перед загрузкой в draft release. Сборка и проверка имеют только `contents: read`; отдельный publish job получает разрешение на создание draft release.

Дополнительная установка x64 пакета проверяет, что Windows принимает пакет с опубликованным сертификатом, а изменения подписанной ZIP-метаинформации блокируют установку. Она выполняется только на одноразовом GitHub runner; проверка ARM64 остаётся статической до теста на ARM64 устройстве.

## Проверки перед полевой установкой

Публикация этой предварительной версии требует успешного release workflow для обоих архитектурных пакетов и успешной проверки установки x64 на одноразовом Windows runner. Локальный прогон должен включать locked restore, Debug build с `-warnaserror`, unit и integration tests, а также тесты release helper.

Перед стабильным выпуском проверьте на целевой машине:

- Overview, страницу провайдера, Dock, actions, переключение настроек, ошибки и stale state, а также штатное завершение COM host;
- удерживаемые объекты, allocations/GC и UI events после повторных переключений и продолжительной работы в Command Palette;
- ARM64 runtime на совместимом устройстве;
- подписанное обновление с предыдущего MSIX с сохранением settings и provider secrets. Для переустановки используйте только процедуру с `Remove-AppxPackage -PreserveApplicationData`.

После публикации артефакты будут на [странице v0.0.5.3](https://github.com/NFoxNet/tokens_bar_pt_palette/releases/tag/v0.0.5.3). Ссылка `releases/latest` останется на последнем стабильном выпуске. Установка описана в [release.md](release.md).
