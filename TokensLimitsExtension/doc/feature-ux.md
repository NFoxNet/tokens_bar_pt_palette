# Новые функции: настройка и проверка

Документ описывает функциональную ветку `codex/feature-ux-development`. Публичный релиз этих возможностей ещё не опубликован.

## Что меняется

Настройки Dock отделены от включения провайдера: скрытый в Dock провайдер остаётся в общем списке и продолжает получать данные. Порядок и показанный показатель выбираются пользователем. Новая быстрая сводка использует нативное всплывающее окно Command Palette; опция `tokensLimits.dock.summaryEnabled` выключена по умолчанию. Существующее отображение нескольких кнопок сохраняется, пока пользователь не включит опцию.

Подключение провайдеров использует существующие настройки и защищённое хранилище. Страница помогает выбрать провайдера, понять требования авторизации и проверить полученные данные. Она не показывает секретные значения. Для Azure OpenAI проверка deployment остаётся отдельным действием, которое может расходовать ресурсы.

## Настройки Dock

| Ключ | Значения и поведение |
| --- | --- |
| `tokensLimits.dock.summaryEnabled` | `false` по умолчанию; включает единую сводку |
| `tokensLimits.dock.providers.<id>.visible` | `true` по умолчанию; скрывает только из Dock |
| `tokensLimits.dock.providerOrder` | Список provider ID через запятую; остальные идут в прежнем порядке |
| `tokensLimits.dock.metric` | `all` по умолчанию; `primary`, `secondary`, `balance` |

Для отсутствующего показателя выводится сообщение о недоступности; другой показатель не подставляется вместо выбранного. Повторяющиеся и неизвестные ID порядка не создают новые элементы.
## Уведомления

`tokensLimits.notifications.enabled` включает наблюдение; по умолчанию выключено. `tokensLimits.notifications.threshold` задаёт остаток в процентах (1–99, по умолчанию 10). Уведомление возникает при переходе через порог, а не при каждом обновлении или первом запуске с низким остатком. Подтверждённый сброс фиксированного окна может дать отдельное уведомление; изменение rolling window само по себе не считается сбросом.

Доставка использует штатное кратковременное сообщение Command Palette. Это не журнал уведомлений Windows. Наблюдение работает, пока процесс расширения запущен. Оценки по локальным журналам, ошибки, устаревшие данные и баланс без известного лимита не запускают уведомления.

## История и темп

`tokensLimits.history.enabled` включает запись; по умолчанию выключено. `tokensLimits.history.retentionDays` выбирает 7, 14 или 30 дней (по умолчанию 14). Измерения сохраняются не чаще одного раза в 5 минут на провайдера, максимум 8640 записей. Выключение прекращает запись, но не удаляет данные. Очистка выполняется отдельным действием на странице истории при включённой опции.

Сохраняются числовые значения и необходимые границы окон. Секреты, названия файлов сессий, тексты пользователя, исходные ответы API и идентификаторы аккаунтов в историю не записываются. Локальный источник, API, изменение настройки или известного аккаунта начинают отдельные сегменты. При неизвестном аккаунте новый запуск процесса начинает новый сегмент; непрерывность между запусками не предполагается.

Прогноз доступен только для явно подтверждённого фиксированного окна: не менее трёх свежих измерений за 15 минут, без больших пропусков, смены сегмента или сброса. Duration/reset без явной семантики фиксированного периода недостаточны. Rolling windows и локальные оценки исключены. Поэтому для многих провайдеров будет показано «Недостаточно данных» даже при наличии истории. Прогноз всегда является оценкой. Он относится только к текущей серии успешных API-измерений и перепроверяется при чтении страницы и событиях кэша, без отдельного таймера. После перезапуска или смены серии нужны новые сопоставимые измерения; прежние записи остаются видны в истории. Подтверждённых реальных ответов провайдеров с подходящими фиксированными границами в этой проверке не было; доступность прогноза нельзя обещать по одним unit-тестам.

Ошибки чтения/записи истории выводятся безопасным сообщением. Повреждённый или слишком большой файл не перезаписывается новой пустой историей.

## Группировка настроек

Пять компактных раскрываемых разделов заменяют длинную общую форму. Подключение каждого провайдера открывается отдельной карточкой; Dock показывает переключатели только включённых провайдеров. Порог уведомлений и срок истории доступны после включения функции и сохранения. Все входы в настройки ведут в одну форму. Ключи и защищённые секреты сохранены; подробнее — [настройки](operations.md).

## Ручная проверка в PowerToys

После Debug Deploy и Reload, с сохранением существующих настроек:

Проверить пять разделов и карточки разных провайдеров: сохранить общие параметры, затем сверить остальные значения и маски секретов; включить историю/уведомления, сохранить и проверить появление зависимых полей; выключить и повторно включить провайдера, проверить сохранность его Dock-видимости. Проверить русский/английский интерфейс, узкое окно, длинные подсказки, раскрытие/сворачивание вложенных карточек и ошибки ввода. Эти живые UI-сценарии не заменяются проверкой структуры Adaptive Cards.

1. Проверить прежний Dock с выключенной сводкой, оба языка и обновление cached snapshot без мигания.
2. Скрыть/переставить провайдера в Dock; убедиться, что overview не потерял его.
3. Включить сводку, открыть flyout и проверить длинные названия/значения, источник, дату и предупреждение ошибки. Выключить сводку и проверить прежние закреплённые команды.
4. Открыть подключение: выключенный провайдер, отсутствующая авторизация, временная ошибка, подключение без квоты. Убедиться, что Azure не запускает inference автоматически.
5. Включить уведомления и проверить один переход через порог, повторные обновления и восстановление остатка. Проверить, что отключение прекращает доставку.
6. Включить историю, дождаться допустимого интервала и открыть записи. Очистить историю отдельным действием; старый снимок не должен вернуться без нового обновления. Проверить выключение записи без удаления файлов и смену настроек/аккаунта без смешения сегментов.
7. Проверить прогноз только на сопоставимых данных текущей серии фиксированного окна. После перезапуска, смены аккаунта/источника, ошибки или устаревания данных прогноз должен исчезнуть; старые записи истории сохраняются. Для rolling/estimate/пропусков прогноз недоступен.

Live-проверка Dock/flyout, ARM64 runtime и обновления реальных пользовательских настроек фиксируется отдельно от unit/integration tests. Установка и переключение регистрации должны следовать `release.md`, без удаления подписанного Release MSIX.

## Проверено при реализации

На продуктовой версии ветки `2e43776` выполнены restore, полная сборка Debug x64 (0 предупреждений и ошибок) и все 257 Core + 141 integration tests. Проверки выполнялись offline с фиктивными провайдерами и временными каталогами: defaults, смена опций и языка, подписки, кэш, настройки подключения, пределы истории, ошибка записи/чтения, явная очистка, переходы источника/аккаунта/цикла и прогноз.

Независимое ревью подсистем и всей ветки завершено; найденные важные замечания закрыты с регрессионными тестами. [Отчёт о проверке](feature-ux-verification.md) содержит детали. Live PowerToys, ARM64 и обновление реальных пользовательских настроек не проверены; мобильная проверка к нативному расширению Windows не применима.

## Принятые решения

- Фиксированное окно требует явных `StartsAt`/`IsFixedWindow`; ошибочную семантику можно исправить в адаптере без выдумывания квоты.
- Помощник использует существующие detail pages; изменение этой связи потребует корректировки навигации.
- Пропуск начинает новый непрерывный участок истории; при необходимости правило допуска прогноза можно ужесточить.
- Уведомления используют кратковременное штатное сообщение Command Palette; для журнала Windows понадобится другая доставка.
- Контроллер истории находится в Core и используется страницей; изменение границы слоёв потребует переноса связки, а не нового хранилища.
