# TokensLimitsExtension v0.0.5.6 — стабильный релиз

## Исправления

- Установщик после in-place обновления проверяет закреплённые полосы Command Palette. Если у Tokens Limits осталась старая identity пакета, он обновляет только `ProviderId` стабильной band-команды до identity установленного MSIX.
- Миграция охватывает общую раскладку Dock и индивидуальные раскладки настроенных мониторов. Перед атомарной записью создаётся копия исходного `settings.json` рядом с ним.
- Если Command Palette ещё запущена, настройки остаются нетронутыми; установщик сообщает, что нужно закрыть/перезагрузить Command Palette и закрепить Tokens Limits заново в `Settings > Dock > Bands`.
- После успешных сборки, проверки подписанного x64/ARM64 MSIX и Windows deployment gate workflow публикует стабильный GitHub Release, а не prerelease или draft.

## Проверки

- Тесты установщика проходят в Windows PowerShell 5.1 на временном JSON fixture: глобальный pin, customized monitor pin, сохранение посторонних настроек, резервная копия, fail-closed для повреждённого JSON и идемпотентность.
- В тесте проверен порядок `остановить PowerToys → установить пакет → мигрировать Dock pin → запустить PowerToys` и отсутствие миграции после неудачной установки.
- Автоматическая проверка workflow собирает и тестирует x64, структурно проверяет обе архитектуры и устанавливает x64 пакет на одноразовый Windows runner.

## Полевое подтверждение

Локальные данные подтвердили одну устаревшую запись Dock для Tokens Limits (`0.0.2.0`), тогда как текущий установленный пакет — `0.0.5.5`; настройки Codex и DeepSeek включены. Журнал Command Palette подтверждает загрузку одной команды и одного band. Причина показанной пустой страницы `Enabled providers` по журналам не установлена, поэтому её исправление не заявляется.

После установки проверьте в Command Palette:

- отображается ли Tokens Limits в `Enabled providers`;
- вернулся ли прежний закреплённый Tokens Limits band;
- сохраняются ли Codex/DeepSeek настройки и provider secrets после обновления поверх установленного MSIX.

Проверки на ARM64 устройстве и live UI/runtime остаются за пользователем.
