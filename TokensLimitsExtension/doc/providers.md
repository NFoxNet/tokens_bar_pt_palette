# Провайдеры

## Каталог и идентификаторы

Единственный источник истины для поддерживаемых провайдеров — `UsageProviderDescriptorRegistry.All`. Порядок списка является порядком в настройках и UI. ID провайдера используется в ключах настроек, URI/ID команд, кэшах и тестах; после публикации его нельзя менять без миграции.

Сейчас каталог включает Codex и набор API-, OAuth-, Cookie- и локальных провайдеров, среди которых Abacus AI, Alibaba Coding Plan, Amp, Anthropic/Claude, AWS Bedrock, Copilot, Cursor, DeepSeek, Gemini, Kiro, OpenAI, OpenRouter, Vertex AI, Windsurf, xAI, z.ai, Zed и другие. Точный список и поля всегда сверяйте с registry: провайдеры и endpoint-детали меняются чаще этой страницы.

Наличие записи в каталоге означает, что расширение умеет хранить её конфигурацию и пытается получить доступные метрики; это не заменяет проверку на реальном аккаунте. Адаптеры, работающие с console/dashboard или Cookie, особенно чувствительны к изменениям частных web-контрактов и должны получать fixture-тесты при каждом обновлении контракта.

## Какие данные доступны

Таблица описывает назначение текущих адаптеров по коду, а не гарантирует
доступность внешнего сервиса или одинаковые права каждого аккаунта. Для точных
полей настроек сверяйте descriptor; список endpoint находится в
`UsageProviderEndpointCatalog`, специальные протоколы — в `ConfiguredUsageProvider`.

| Провайдер / источник | Результат | Авторизация и ограничения |
| --- | --- | --- |
| Codex usage | Окна квоты, тариф, дополнительные лимиты | OAuth из `auth.json` первого Codex home; источник должен вернуть окна |
| Codex session fallback | Количество токенов за 5 часов и 7 дней, явно оценка | Локальные JSONL из всех заданных home; это не остаток аккаунтной квоты |
| DeepSeek | Баланс с валютой; дополнительные доступные метрики | API key; неполные данные не превращаются в процент |
| Amp, Kilo, OpenRouter | Баланс/кредиты и опубликованные ограничения плана | Ключ или предусмотренный web-источник; разные валюты не суммируются |
| OpenAI organization usage/costs | Токены, запросы, расходы за выбранный период | Для organization endpoints обычно нужен Admin API key и права на выбранный project/account; обычного model API key может быть недостаточно |
| MiniMax, Kimi, Alibaba Coding Plan, z.ai | Окна/кредиты/метрики, реально присутствующие в ответе | Поля региона, scope и ключ/Cookie зависят от descriptor; не выводятся квоты по одному названию тарифа |
| JetBrains AI | Значения quota-файла | Локальный XML выбранного профиля; наличие файла не гарантирует свежесть сетевой квоты |
| Kiro | Результат usage-команды CLI | Доступный `kiro-cli` и его авторизованная сессия; процесс ограничен timeout и размером вывода |
| Windsurf | Plan status и опубликованные кредитные/лимитные метрики | Session bundle авторизованной сессии; protobuf-контракт может изменяться |
| Ollama local | Каталог установленных моделей | Локальный endpoint; число моделей не является usage или процентом квоты |
| Ollama cloud | Опубликованные cloud-квоты/метрики либо каталог | Настроенный API/Cookie; доступность зависит от реально выбранного источника |
| Azure OpenAI | Автоматически — сообщение об отсутствии quota; вручную — проверка подключения deployment | Проверка явно выполняет один `chat/completions` запрос и может расходовать ресурсы deployment; токены этого ping не выдаются за расход аккаунта |
| Остальные API/OAuth adapters | Только распознанные окна, баланс, расход или иные `UsageMetric` | Используется настроенный ключ/токен и предусмотренный endpoint; каталог не доказывает поддержку каждого live response |
| Остальные Cookie/dashboard adapters | Только данные авторизованного web-источника | Cookie и права аккаунта; private web contract требует fixture-проверки при изменениях |

Если источник не публикует quota, интерфейс показывает подходящую метрику или
явное сообщение об отсутствии quota. Он не выводит искусственный процент по
балансу, числу моделей, успешному подключению или названию плана. В сводке
длительности окон берутся из `LimitWindowSeconds`; отсутствующее окно не
подменяется обязательным слотом «5 часов / 7 дней».

## Типы авторизации

- `OAuth` — локальный OAuth/credentials или токен клиента.
- `ApiKey` — ключ API, обычно с переменной окружения.
- `Cookie` — авторизованный Cookie-заголовок веб-кабинета.
- `ApiKeyOrCookie` и `OAuthOrCookie` — несколько допустимых источников.
- `Local` — локальный файл, каталог или CLI без сетевого запроса.

Секретные поля помечаются в дескрипторе и попадают в защищённое хранилище. Незаполненное поле может иметь fallback на переменную окружения, если это явно задано в `UsageProviderSettingDescriptor`.

## Как добавить провайдера

1. Добавьте `UsageProviderDescriptor` в `UsageProviderDescriptorRegistry.All` в нужной позиции. Укажите стабильный lowercase ID, display name, auth kind, dashboard URL, настройки и описание источника.
2. Реализуйте обработку ID и endpoint в `ConfiguredUsageProvider` или выделите небольшой provider-specific adapter, если логика сложная.
3. Нормализуйте ответ в `UsageSnapshot`: окно только при наличии реальных `used/reset/limit` данных; прочие значения кладите в `Metrics`.
4. Обработайте отсутствие ключа, неверный JSON, HTTP errors, timeout, cancellation и rate limiting.
5. Не логируйте секреты и не сохраняйте полный ответ провайдера в файл.
6. Добавьте тесты для request method/URL/headers/body и для разных вариантов ответа.
7. Проверьте отображение в overview, detail page и dock band.
8. Обновите этот документ и при необходимости [operations.md](operations.md).

## Правила качества данных

- `UsedPercent` должен быть конечным числом в диапазоне 0–100.
- `LimitWindowSeconds` должен быть положительным.
- Unix timestamp может быть в секундах или миллисекундах, но преобразование должно быть проверяемым тестом.
- Если провайдер сообщает только баланс/кредиты/число запросов, используйте `UsageMetric` с исходными единицами.
- Если данные получены из локального fallback или рассчитаны по событиям, выставляйте `IsEstimate = true`.
- Локальный Codex fallback публикует `UsageMetric` с `SemanticKey` `tokens5h` и `tokens7d`; эти значения являются количеством токенов, а не процентом квоты. Не добавляйте условные лимиты или reset dates.
- Не маскируйте ошибку провайдера «нулевым» snapshot: UI должен показать, что данные недоступны.

## Повторное использование кэша

Провайдеры создаются заранее, но запросы должны начинаться только для включённых поверхностей. `UsageSnapshotCache` обеспечивает single-flight refresh и last-known snapshot. Не обходите его прямым сетевым вызовом из страницы или dock band.

Все HTTP-адаптеры должны преобразовывать неуспешный ответ в `UsageProviderRequestException` с `StatusCode` и доступным `RetryAfter`. Внешний CLI запускается через `IUsageProviderProcessRunner`: deadline, отдельные пределы stdout/stderr, `CreateNoWindow`, `ArgumentList`, `UseShellExecute = false` и завершение дерева процесса являются обязательной границей. Полный ответ API, Cookie и credentials в логах запрещены.
