# Провайдеры

## Каталог и идентификаторы

Единственный источник истины для поддерживаемых провайдеров — `UsageProviderDescriptorRegistry.All`. Порядок списка является порядком в настройках и UI. ID провайдера используется в ключах настроек, URI/ID команд, кэшах и тестах; после публикации его нельзя менять без миграции.

Сейчас каталог включает Codex и набор API-, OAuth-, Cookie- и локальных провайдеров, среди которых Abacus AI, Alibaba Coding Plan, Amp, Anthropic/Claude, AWS Bedrock, Copilot, Cursor, DeepSeek, Gemini, Kiro, OpenAI, OpenRouter, Vertex AI, Windsurf, xAI, z.ai, Zed и другие. Точный список и поля всегда сверяйте с registry: провайдеры и endpoint-детали меняются чаще этой страницы.

Наличие записи в каталоге означает, что расширение умеет хранить её конфигурацию и пытается получить доступные метрики; это не заменяет проверку на реальном аккаунте. Адаптеры, работающие с console/dashboard или Cookie, особенно чувствительны к изменениям частных web-контрактов и должны получать fixture-тесты при каждом обновлении контракта.

## Типы авторизации

- `OAuth` — локальный OAuth/credentials или токен клиента.
- `ApiKey` — ключ API, обычно с переменной окружения.
- `Cookie` — авторизованный Cookie-заголовок веб-кабинета.
- `ApiKeyOrCookie` и `OAuthOrCookie` — несколько допустимых источников.
- `Local` — локальный файл, каталог или CLI без сетевого запроса.

Секретные поля помечаются в дескрипторе и попадают в защищённое хранилище. Незаполненное поле может иметь fallback на переменную окружения, если это явно задано в `UsageProviderSettingDescriptor`.

## Как добавить провайдера

1. Добавьте `UsageProviderDescriptor` в `UsageProviderDescriptorRegistry.All` в нужной позиции. Укажите стабильный lowercase ID, display name, auth kind, dashboard URL, настройки и описание источника.
2. Реализуйте обработку ID и endpoint в `ConfiguredUsageProvider` или выделите небольшой provider-specific adapter, если логика сложная.
3. Нормализуйте ответ в `UsageSnapshot`: окно только при наличии реальных `used/reset/limit` данных; прочие значения кладите в `Metrics`.
4. Обработайте отсутствие ключа, неверный JSON, HTTP errors, timeout, cancellation и rate limiting.
5. Не логируйте секреты и не сохраняйте полный ответ провайдера в файл.
6. Добавьте тесты для request method/URL/headers/body и для разных вариантов ответа.
7. Проверьте отображение в overview, detail page и dock band.
8. Обновите этот документ и при необходимости [operations.md](operations.md).

## Правила качества данных

- `UsedPercent` должен быть конечным числом в диапазоне 0–100.
- `LimitWindowSeconds` должен быть положительным.
- Unix timestamp может быть в секундах или миллисекундах, но преобразование должно быть проверяемым тестом.
- Если провайдер сообщает только баланс/кредиты/число запросов, используйте `UsageMetric` с исходными единицами.
- Если данные получены из локального fallback или рассчитаны по событиям, выставляйте `IsEstimate = true`.
- Не маскируйте ошибку провайдера «нулевым» snapshot: UI должен показать, что данные недоступны.

## Повторное использование кэша

Провайдеры создаются заранее, но запросы должны начинаться только для включённых поверхностей. `UsageSnapshotCache` обеспечивает single-flight refresh и last-known snapshot. Не обходите его прямым сетевым вызовом из страницы или dock band.
