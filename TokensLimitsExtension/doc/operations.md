# Настройки, безопасность и диагностика

## Настройки пользователя

Основные настройки создаются динамически из каталога провайдеров:

- `tokensLimits.refreshInterval` — секунды между обновлениями, от 30 до 3600, по умолчанию 60.
- `tokensLimits.providers.<providerId>.enabled` — включение провайдера.
- `tokensLimits.providers.<providerId>.<field>` — provider-specific поле.

Обычные settings и secrets находятся в отдельных JSON-файлах в едином каталоге `%LOCALAPPDATA%\TokensLimitsExtension` (`tokensLimits.settings.json` и `tokensLimits.secrets.json`). После обновления расширение один раз мигрирует найденные host/package-local файлы в этот каталог; старые копии не используются. Не копируйте эти файлы в issue или pull request целиком.

Для Codex расширение читает `$CODEX_HOME\auth.json` (или `%USERPROFILE%\.codex\auth.json`). Размер локального auth-файла ограничен 1 MiB, чтобы повреждённый или подменённый файл не создавал неограниченные аллокации. Если OAuth возвращает ротацию токена, обновлённая пара атомарно записывается обратно только когда файл не был изменён Codex CLI во время запроса; изменение файла CLI подхватывается при следующем обновлении. Содержимое этого файла также является секретом.

Переменные окружения провайдеров указаны рядом с полями в `UsageProviderDescriptorRegistry.cs`. Для Codex:

- `CODEX_HOME` может содержать один или несколько путей через запятую;
- по умолчанию используется `%USERPROFILE%\.codex`;
- auth читается из `auth.json` внутри Codex home.

## Безопасность

- API keys, cookies, OAuth tokens и credentials JSON считаются секретами.
- Локальные provider-файлы (JSON/XML и Kilo CLI auth) читаются с пределом 1 MiB; превышение классифицируется как неподдерживаемый ответ и не передаётся парсеру.
- Не добавляйте их в исходники, тестовые fixtures, логи, screenshots или commit messages.
- Секретные настройки маскируются в UI и сохраняются через `ProtectedSecretStore`.
- Изменение настроек одного провайдера очищает только его cache; переключение языка и неизменившийся refresh interval не сбрасывают account data.
- При диагностике используйте provider ID, HTTP status, размер ответа и тип ошибки; удаляйте значения заголовков и тела.
- Не расширяйте разрешения и не меняйте endpoint на HTTP. Для Codex usage endpoint применяется HTTPS-проверка.
- На detail page действие «Открыть кабинет» строится только из `DashboardUrl` доверенного descriptor и разрешает исключительно HTTPS. Текст ошибки никогда не превращается в ссылку.
- Действие «Скопировать безопасную диагностику» содержит только provider ID, тип ошибки, признак устаревшего snapshot и Retry-After; ключи, Cookie, OAuth и тела ответов туда не попадают.

## Что проверить при «нет данных»

1. Провайдер включён в настройках.
2. Заполнен нужный ключ/Cookie/OAuth-параметр или доступна соответствующая переменная окружения.
3. Для локального источника существует путь к файлу/CLI и процесс имеет права чтения/запуска.
4. После изменения настроек выполнено `Reload` в Command Palette.
5. В Output window нет timeout, HTTP status или ошибки схемы ответа.
6. Для Codex доступен `auth.json`; если официальный путь недоступен, UI может показать оценку по локальным сессиям.
7. Используйте подсказку «следующий шаг» на detail page: она различает отсутствующую конфигурацию, авторизацию, rate limit, сеть/timeout и несовместимый ответ.

## Интерпретация отображения

- В UI показывается остаток окна, хотя в модели хранится `UsedPercent`.
- «Оценка» означает `IsEstimate = true`, а не подтверждённую квоту API.
- `—` или «данные недоступны» означает, что провайдер не дал соответствующее значение; это не обязательно нулевой расход.
- Время сброса форматируется относительно текущего UTC-времени.

## Диагностический цикл

```text
изменить настройки
  -> Reload extension
  -> открыть Tokens Limits
  -> открыть страницу провайдера
  -> проверить Output window
  -> воспроизвести через существующий unit test/stub
```

При сообщении об ошибке приложите версию расширения, Windows/архитектуру, provider ID, режим источника и обезличенный статус/текст ошибки. Секреты и полные ответы API не прикладывайте.
