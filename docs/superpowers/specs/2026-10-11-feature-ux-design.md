# Развитие Tokens Limits: функции и удобство

Дата: 2026-10-11. Статус: согласовано пользователем 2026-10-11; реализация ведётся по отдельному плану.

## Цель и согласованный объём

Упростить повседневное наблюдение за лимитами из PowerToys Command Palette: персональный Dock, подключение провайдеров, опциональная быстрая сводка, уведомления, локальная история и осторожная оценка темпа расхода. Не создавать отдельное приложение или постоянно работающий сервис.

## 1. Персональный Dock

Включение провайдера для получения данных и его видимость в Dock — отдельные настройки. По умолчанию видны все включённые провайдеры, как сейчас. Пользователь может задать порядок; неизвестные и повторяющиеся идентификаторы не создают дубликатов. Новые провайдеры дополняют конец списка. Настройка показателя позволяет выбрать все доступные значения, основное окно, дополнительное окно или баланс. Недоступное значение явно отмечается, процент не придумывается. Overview сохраняет всех включённых провайдеров.

## 2. Быстрая сводка во всплывающем окне

Отдельная настройка `tokensLimits.dock.summaryEnabled`, по умолчанию `false`, переключает Dock между существующими кнопками провайдеров и одной нативной кнопкой со сводкой. Использовать поддерживаемую Command Palette content page, без собственного окна. Сводка содержит видимых в Dock провайдеров в заданном порядке, их доступные показатели, время получения, источник и предупреждение об устаревших данных. Обновление читает общий cache; сеть из GetItems/GetContent запрещена. При наличии snapshot фоновое обновление не меняет подпись кнопки. Переключение режима сохраняет стабильный band ID и существующие provider command IDs. При выключенной опции сводка не подписывается на cache и не создаёт дополнительных фоновых задач.

## 3. Подключение провайдеров

Нативная страница выбора провайдера показывает необходимые поля, источник авторизации и следующие действия. Использовать существующие настройки и защищённое хранилище секретов. Секреты не выводить в Markdown, диагностику или историю. После настройки пользователь получает понятный результат: данные получены, требуется авторизация, временная ошибка или API не предоставляет квоту. Azure inference validation запускается только отдельным явным действием с предупреждением о расходе ресурсов.

## 4. Уведомления

Опция выключена по умолчанию. При включении: одно уведомление при переходе ниже выбранного остатка (по умолчанию 10%) и одно при подтверждённом сбросе окна. Проверять только свежие подтверждённые проценты; estimates, ошибки, устаревшие данные и баланс без лимита исключить. Дедупликация по провайдеру, источнику, аккаунту при известной идентичности и циклу окна; сброс после смены конфигурации. Никаких уведомлений на каждом refresh. Доставка через поддерживаемый Windows/Command Palette механизм без нового сервиса. Наблюдение действует только пока процесс расширения работает; это явно указать в настройках и документации.

## 5. Локальная история

Опция выключена по умолчанию. При включении сохранять только нормализованные числовые показатели, timestamps, идентификатор провайдера, источник и необходимые сведения о цикле окна. Без credentials, полных ответов API, названий файлов сессий и пользовательских текстов. Хранение 14 дней по умолчанию с выбором 7/14/30 дней, не чаще одного измерения на провайдера за 5 минут, жёсткий предел 8640 записей на провайдера. Ограничить размер файла перед чтением, писать атомарно. Нельзя смешивать API и локальные estimates, аккаунты или данные до/после смены конфигурации. Когда надёжная идентичность аккаунта недоступна, новый запуск начинает отдельный сегмент; не обещать непрерывность между аккаунтами. Пропуски не превращаются в нули. Страница истории показывает небольшой список измерений средствами Command Palette. Есть явное действие очистки сохранённой истории; выключение останавливает запись, но не удаляет данные молча.

## 6. Темп расхода

Показывать только при включённой истории и не менее трёх свежих сопоставимых измерениях одного фиксированного окна за период не меньше 15 минут. Сравнивать расход с прошедшей долей окна только если известны достоверные границы; рассчитывать примерное время исчерпания только при положительном расходе. Rolling windows, estimates, смена аккаунта/источника, reset и пропуски исключаются. Недостаточные данные дают понятную подпись вместо выдуманного прогноза. Любой прогноз помечается как оценка.

## Архитектура и совместимость

Модели, история, дедупликация и расчёты относятся к Core; страницы, настройки и доставка уведомлений — к UI. Использовать существующий UsageRefreshCoordinator, UsageSnapshotCache, JsonSettingsManager и EN/RU словари. Не добавлять зависимости, отдельные таймеры или сетевые запросы ради новых поверхностей. Сохранить COM hosting, CLSID, package identity, существующие settings/provider/command IDs. Старые настройки сохраняют прежнее поведение; новые возможности отключены по умолчанию, кроме прежнего отображения Dock.

## Последовательность реализации

1. Настройки персонального Dock и опциональная сводка.
2. Подключение провайдеров.
3. Уведомления после проверки поддерживаемого механизма доставки.
4. Ограниченная история и её страница.
5. Оценка темпа поверх истории.

Для каждого шага: тесты поведения и EN/RU, документация, отдельный проверяемый патч. Публикация новой версии и релиза — отдельный этап по запросу пользователя.

## Проверки и критерии приёмки

- Старые настройки сохраняют видимые кнопки Dock; новая сводка выключена по умолчанию.
- Переключение сводки и видимости не отключает получение данных для overview и не теряет host pin IDs.
- Refresh с прежним snapshot не вызывает мигания Dock; выключенные поверхности не держат лишние подписки.
- Смена языка, credentials и состава провайдеров корректно обновляет UI без утечки старых данных.
- Уведомления не повторяются, не срабатывают по estimates и не выдают неизвестный reset за подтверждённый.
- История ограничена по времени, количеству и размеру файла; повреждения видны пользователю и не затираются молча.
- Прогноз не объединяет разные циклы, источники или аккаунты.
- Unit/integration tests не используют интернет или реальные credentials.
- Debug build/test x64; live PowerToys Dock/flyout и обновление существующих настроек проверяются отдельно. ARM64 runtime не считается проверенным по результату x64 тестов.

## Открытый риск

Поддержка нативного flyout и доставки уведомлений зависит от SDK и версии PowerToys. Перед написанием соответствующей реализации проверить официальные контракты; если платформа не обеспечивает нужное поведение, зафиксировать ограничение и согласовать замену, не маскировать её собственным окном или фоновым сервисом.
